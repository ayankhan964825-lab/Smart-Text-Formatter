1. ABSTRACT

This project report introduces the "FormatxFlow", a robust web application engineered to demonstrate the power of Object-Oriented Programming and Design (OOPD) within modern frontend architecture. With the exponential growth of raw digital text, professionals often spend excessive time manually adjusting headings and formatting long documents. Our system resolves this inefficiency by employing a strict 4-Stage OOP pipeline (TextProcessor, StructureDetector, RuleEngine, OutputGenerator) combined with Google Gemini AI to fully automate document structuring.

Developed collaboratively by Mohd Ayan Khan, Tapish Ganesh Ingle, and Shreyansh Singh under the guidance of Dr. Umma Meena, this application emphasizes strict encapsulation, modularity, and polymorphism. By isolating the Gemini API logic inside polymorphic extensions like AIFormatter, the system acts as a pure, dependency-free client-side solution. The research herein details how applying rigorous software engineering principles prevents spaghetti code and ensures seamless export to DOCX and PDF formats.

The integration of Object-Oriented Programming and Design (OOPD) principles within text processing pipelines fundamentally shifts how unstructured data is normalized. Our AI Formatting system intelligently categorizes raw input streams by instantiating modular, reusable class objects such as TextProcessor and StructureDetector. A core philosophy of this project is Encapsulation. By actively hiding internal data states (e.g., rawText within TextProcessor and defaultRules within RuleEngine), we prevent global scope pollution. Furthermore, Abstraction allows the main execution thread (e.g., app.js) to invoke formatText() without needing any understanding of the underlying heuristic parsing logic versus the Gemini AI execution flow.

We designed the architecture to readily support Inheritance and Polymorphism. The baseline StructureDetector can be cleanly extended by a new MarkdownDetector subclass. Additionally, processing pipelines like AIFormatter and the baseline heuristic module share polymorphic interfaces, allowing the execution pipeline to seamlessly transition between AI-assisted formatting and offline parsing based on network availability. 6.1 TextProcessor Class (Encapsulation and Single Responsibility)

This class strictly handles data ingestion and raw tokenization. It isolates the raw string manipulation away from the styling logic.

class TextProcessor {
    constructor(rawText) {
        // Encapsulated state preventing external corruption
        this._rawText = rawText; 
        this.tokens = [];
    }

    normalize() {
        if (!this._rawText) throw new Error("No text provided.");
        this._rawText = this._rawText.trim().replace(/\r\n/g, "\n");
        return this; // Supporting method chaining
    }

    tokenize() {
        this.tokens = this._rawText.split("\n\n");
        return this.tokens;
    }
}

6.2 RuleEngine Class (Abstraction and Customization)

The CSS styling mapping is abstracted within this class. The UI does not know how paragraphs map to specific dimensions; it relies entirely on the engine's internal dictionary mapping.

class RuleEngine {
    constructor(customRules = {}) {
        this.defaultRules = {n 
            h1: { fontSize: '24pt', fontWeight: 'bold' },
            h2: { fontSize: '18pt', fontWeight: 'bold' },
            p:  { fontSize: '12pt', lineHeight: '1.5' }
        };
        // Safely merges user-defined overrides securely
        this.rules = { ...this.defaultRules, ...customRules };
    }

    applyRules(elementNodeList) {
        elementNodeList.forEach(node => {
            const rule = this.rules[node.tagName.toLowerCase()];
            if (rule) {
                Object.assign(node.style, rule);
            }
        });
        return elementNodeList;
    }
}

6.3 AIFormatter Extension (Polymorphism and Inheritance)

Polymorphic design allows the central application to call format() universally. The AIFormatter executes a completely separate RESTful execution flow under the hood.

class AIFormatter {
    constructor(apiKey) {
        // Securely encapsulate credentials
        this._apiKey = apiKey;
        this.apiUrl = "https://generativelanguage.googleapis.com/v1beta/models/gemini-pro:generateContent";
    }

    async formatText(processorInstance) {
        const text = processorInstance.normalize()._rawText;
        const prompt = "Format this unstyled text accurately into structured HTML tags: " + text;
        
        try {
            const response = await fetch(this.apiUrl + "?key=" + this._apiKey, {
                method: 'POST',
                headers: { 'Content-Type': 'application/json' },
                body: JSON.stringify({
                    contents: [{ parts: [{ text: prompt }] }]
                })
            });
            const data = await response.json();
            return data.candidates[0].content.parts[0].text;
        } catch (error) {
            console.error("Polymorphic fallback required:", error);
            throw error;
        }
    }
}

  • Context Window Constraints: Extremely massive books (e.g., 500+ pages) may breach the active AI token parsing limits requiring chunked execution.
  • Browser Isolation: Heavy PDF Blob generations can occasionally cause mobile browsers (specifically iOS Safari) to suffer memory-crashes.

Our AI Formatting system intelligently categorizes raw input streams by instantiating modular, reusable class objects such as TextProcessor and StructureDetector. A core philosophy of this project is Encapsulation. By actively hiding internal data states (e.g., rawText within TextProcessor and defaultRules within RuleEngine), we prevent global scope pollution. Furthermore, Abstraction allows the main execution thread (e.g., app.js) to invoke formatText() without needing any understanding of the underlying heuristic parsing logic versus the Gemini AI execution flow.

We designed the architecture to readily support Inheritance and Polymorphism. The baseline StructureDetector can be cleanly extended by a new MarkdownDetector subclass.
