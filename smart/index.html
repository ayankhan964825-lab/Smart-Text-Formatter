The Core NLP Problem

Structuring the Unstructured

In data processing, dealing with raw strings is notoriously difficult. Working with raw text presents two major bottlenecks:

📜

Semantic Intent

Computers don't inherently know if a line of text is a `Heading`, a `Bullet Point`, or a normal `Paragraph`. Understanding the intent requires reading the context.

⚠️

OCR Artifacts

Extracting data from PDFs or images injects severe noise: random line breaks overriding sentences, or floating strings like `[Page 24]` mixed into raw strings.

Our Solution Strategy

Why Not RegEx?

Traditional code relies on Regular Expressions (RegEx) to find patterns. However, language is too highly varied and complex. RegEx breaks easily on edge cases.

❌ Hardcoded Rules Fail ✅ Generative LLMs Succeed

We built a Generative AI pipeline that reads the raw string probabilistically and infers the structural intent with near human-level accuracy.

System Architecture

The AI Bridge

Our frontend interacts with the Google Gemini 2.5 Flash API directly. By removing the backend server entirely, we achieve lower latency and maximum zero-state privacy.

1

Payload

  • Raw unstructured text string is sent over REST to Google API.
2

Inference

  • Gemini calculates semantic probabilities and restructures it.
3

DOM Mapping

  • Client-side JS parses the AI output and dynamically renders DOM blocks.

Prompt Engineering

To prevent the AI from "hallucinating" or chatting conversationally, we use strict System Instructions.

"You are a strict text-formatting engine. Do NOT reply with ANY conversational text. Analyze the input text and classify each block. Respond ONLY with a JSON array."

By forcing the LLM into a specific persona, we guarantee Zero-Shot Task Adherence.

{ }

Deterministic JSON

Predictability is critical in software. An LLM's response is inherently probabilistic. If it returns standard markdown, rendering parsers can break on edge-cases.

We solved this via Structured Outputs. The Gemini model is strictly configured to `response_mime_type: "application/json"`.

{ "type": "h1" } : Top level Title
{ "type": "p" } : Formatted Paragraph
{ "type": "mermaid" } : System Architecture

Context-Aware Filtering

How the LLM handles complex Optical Character Recognition (OCR) garbage:

Stray text: "[page 4]"
Line Break mid-sentence
Semantic Scanning
Probability Rejection
Clean Merged Paragraph

The model identifies that `[page 4]` holds no semantic relevance to the surrounding tokens, and autonomously excises it.

🔄

Autoregressive Self-Healing

Our platform detects processes and commands the AI to generate `Mermaid.js` diagram syntax. But what if the AI generates broken syntax with a missing parenthesis?

The Auto-Healing Loop:

1. JS fails to compile the syntax graph.
2. Evaluator catches the explicit `Error Output`.
3. Sends error back to AI: "Fix this bug."
4. AI parses error and successfully patches code.
